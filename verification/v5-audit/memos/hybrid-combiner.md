# hybrid-combiner (ama_cryptography/hybrid_combiner.py) — classical+PQC KEM shared-secret combiner (HKDF-SHA3-256 binding construction)

SECURE / DEFENDED (no exploitable finding). The hybrid combiner implements the standard RFC-5869 / TLS-1.3-hybrid concatenation-then-KDF construction over native HMAC-SHA3-256, and it correctly achieves the target hybrid property: the 32-byte combined key remains pseudorandom if EITHER the classical (X25519) or the PQC (Kyber-1024) component is unbroken, under the standard random-oracle model for SHA3-256. Placing both component secrets in the HKDF IKM (HMAC message) while binding the public transcript via the salt (HMAC key) is the robust choice — it survives even an adversarially-chosen broken-component secret, avoiding the dual-PRF pitfall. Transcript binding is complete and symmetric between encapsulate and decapsulate: ciphertexts are 4-byte length-prefixed in salt (the C6 fix; kills component stripping/mix-and-match), and label + component_count(2) + both length-prefixed public keys are bound in info. Length-extension is precluded (Keccak sponge + HMAC). INVARIANT-7 is enforced: combine() fails closed if the native KDF is absent and never touches the double-gated test-only Python KDF. The only residual items are LOW severity and non-exploitable in the shipped wiring: (1) the IKM concatenation ss_c||ss_p is not internally length-delimited (INVARIANT-19) — safe only because every production secret is fixed at 32 bytes; it is a latent footgun for any future variable-length caller, and the regression test intended to cover it (test_pr224_followup.py:369) does not actually construct a colliding pair; (2) the domain label is not length-prefixed in info (safe because it is a non-attacker-controlled constant); (3) the production KEM calls combine() directly, so the encapsulate_hybrid/decapsulate_hybrid input-validation wrappers (H4 fix) provide no protection to the shipping path — combine() is permissive by contract, which is acceptable for hybrid security but worth noting. Recommended hardening (defense-in-depth, not blocking): length-prefix the IKM secrets and the label, and either route the production KEM through the validating wrappers or assert fixed 32-byte secret widths inside combine().
