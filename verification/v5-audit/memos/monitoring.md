# monitoring — 3R Runtime Anomaly Monitor (ama_cryptography/monitoring.py, ama_cryptography/monitor.py)

Core security properties are sound and, in several places, defended with unusually careful, well-commented reasoning. The nonce-reuse detector is a true exact-set check with an atomic, fail-closed, injection-safe persistence layer (no false negatives within a process or across a restart). The caller-keyed structures are all bounded and drop-and-count rather than grow, the concurrency is correctly locked, the integrity self-check fails closed, and the calibrated timing thresholds resist naive poisoning. No exploitable break of confidentiality or of nonce-reuse detection was found. The findings are two real defects plus documented advisory limits: (1) MEDIUM — the note-artifact detector only scans head+tail of payloads larger than 8 KiB, so a successor note centered in a >8 KiB blob is never inspected, a cleaner bypass than the vocabulary-avoidance the docstring already concedes (advisory detector, so it costs a review signal, not a crypto guarantee); (2) MEDIUM/availability — the module-level monitor built at crypto_api import reads the default $HOME nonce ledger with an unguarded mkdir and a brick-on-any-malformed-content reload, so a torn write, an unwritable/attacker-controlled HOME, or a large planted file makes the ENTIRE library unimportable (fail-closed but total, with no in-code repair path); (3) LOW — the get_security_report last-10 sliding window can drop an unscored critical under a between-polls flood, bounded by the fact that the posture score ignores nonce/volume/note/integrity types. The remaining timing/volume/CUSUM evasions (warmup blind spots, learned-baseline poisoning, vocabulary avoidance) are inherent to statistical anomaly monitoring and are explicitly documented as advisory. Recommended hardening: scan a middle sample (or reject/flag over-budget payloads) in NoteArtifactDetector._sample and fix the docstring's sampling claim; wrap the module-level monitor's nonce-ledger init in try/except with degradation to ephemeral-plus-loud-warning instead of an import-time raise, and quarantine (rename) rather than refuse a corrupt ledger; consider exporting an alert high-water/overflow indicator so consumers can detect sliding-window loss.
