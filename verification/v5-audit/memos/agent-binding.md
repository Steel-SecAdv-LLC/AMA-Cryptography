# agent-binding (INVARIANT-30 agent-instance key/signature binding): ama_cryptography/agent_binding.py, src/c/ama_agent_binding.c, include/ama_cryptography.h (AGENT-INSTANCE BINDING block, lines ~877-1140)

The C implementation is memory-safe, constant-time by construction, canonically-encoded, and fail-closed; every classic attack against the record itself — tag forgery under K_auth, capability escalation, lifetime downgrade, instance transplant, non-canonical encoding, profile-absence, join-buffer overflow, clause-timing oracle, fail-open — is DEFENDED with code evidence, and the pinned C and Python test suites exercise all of them. The subsystem's one substantive weakness is architectural, not a coding bug: the operator-authorization tag is a symmetric MAC verified against a CALLER-SUPPLIED key, while the two security-relevant outputs (the HKDF-derived key and the SHA3 signing context) are functions of enc(b) ONLY and carry no tag. Consequently, under the mandated adversary model where the attacker controls the authority_key argument (an escaped agent that can call the API, exactly as the module's own usage example depicts), the gate is satisfiable end-to-end with a self-chosen key (authorize(own_key) + derive(own_key)) and yields byte-identical outputs to an operator-authorized flow, and no downstream verifier holding the real K_auth can distinguish authorized from unauthorized because the authorization never travels with the output. This contradicts INVARIANT-30's stated claim that 'an escaped agent still cannot mint a persistent binding'. It is rated medium because it is not exploitable in a strict operator-mediated TCB (agent never calls the API) and because bypassing the gate leaks no secret the subsystem itself holds — the real secrecy of the outputs rests on external ikm and signing keys the subsystem does not manage. Recommendation: either (a) restrict the deployment contract so only trusted code holding K_auth invokes derive_key/signing_context/check (make the module docstring's agent-side derive example non-normative), or (b) bind authorization into the outputs — e.g., mix a value derived from the verified tag (or from K_auth directly) into the HKDF info and the signature-context hash — so that an unauthorized (self-keyed) binding produces provably different, non-honored material rather than identical bytes. The subsystem is otherwise sound and defends its record-level invariants well.
